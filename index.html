Results

Each fuzzing experiment runs for 24 hours and is repeated five times. We adopt edge coverage and the number of unique bugs as evaluation metrics. Edge coverage is measured using afl-showmap; we report the average across five runs. Unique bugs are identified by the call stack reported by ASan, where two crashes sharing the same stack frames are considered duplicates; we report the union across five runs. Full data and reproduction scripts are available in the experiment data artifact. We evaluate RamFuzz by answering three research questions:

  • RQ1: Detection Effectiveness. How effective is RamFuzz at detecting unique bugs and achieving code coverage?
  • RQ2: Runtime Cost. What is the runtime overhead introduced by RamFuzz?
  • RQ3: 0-day Bug Detection. Can RamFuzz effectively identify previously unknown bugs in real-world programs?

Responsible Disclosure

At the time of writing, all newly discovered vulnerabilities have been reported to their respective maintainers. We follow coordinated disclosure practices:

  • Vulnerability descriptions and affected source file names are publicly listed above.
  • Proof-of-concept exploits are withheld until after the camera-ready deadline.
  • Full disclosure will be coordinated with the respective maintainers.
